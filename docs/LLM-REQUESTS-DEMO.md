# LLM Requests — Demo Walkthrough

The exact sequence of LLM round-trips generated by the recorded demo, with
realistic request/response payloads. These are **message-level
reconstructions**: LangChain abstracts Gemini's wire format into this shape —
a list of `system` / `human` / `ai` / `tool` messages plus the **tool
declarations** (function schemas) bound to the model.

**Demo transcript**
1. `My phone number is +55 (12) 3923-5555. How much was my most recent purchase? What albums do you have by the Rolling Stones?`
2. `List some songs that match my preferences?`

> **The one principle that explains everything below:** the LLM never runs your
> Python. Each call returns **either** a `tool_call` (`{name, args}`) **or**
> plain `content`. *Routing between agents* and *calling a tool* are the **same
> primitive** — the model proposes `{name, args}`; LangGraph's runtime executes
> it. A handoff tool's effect is a graph jump; a data tool's effect is running
> your `@tool` function.

How a tool reaches the model: the `@tool` decorator turns each function into a
JSON "function declaration" (name + docstring-as-description + typed params);
`model.bind_tools([...])` ships those with every request. Params marked
`InjectedState` (e.g. `customer_id`) are **hidden** from the model and filled by
the runtime — that is why `args` for invoice tools come back empty.

## TURN 1 — "phone + purchase + Rolling Stones albums"

### Call A — `verify_info`: identifier extraction (structured output)
Structured output = a *forced* function call to the `IdentifierExtraction` schema.

```jsonc
REQUEST:
  tools: [ IdentifierExtraction(identifier_type: enum, value: string) ]   // tool_choice forced
  messages:
    system: "You extract a customer identifier from a support message. Return the
             customer ID, email, or phone if present, else 'none'. Do not invent values."
    human:  "My phone number is +55 (12) 3923-5555. How much was my most recent
             purchase? What albums do you have by the Rolling Stones?"
RESPONSE:
  ai tool_call: IdentifierExtraction { "identifier_type": "phone",
                                        "value": "+55 (12) 3923-5555" }
```
→ no further LLM in this node; `_lookup_customer_id` runs pure SQL → `customer_id="1"`.

### Call B — `supervisor`: first routing decision
```jsonc
REQUEST:
  tools: [ transfer_to_music_catalog, transfer_to_invoice_info ]
  messages:
    system: "You are a customer-support supervisor managing two agents… a single
             request may need BOTH agents… after one replies, check if any part is
             still unanswered and delegate again before finishing."
    human:  "My phone number is … How much was my most recent purchase? What albums
             do you have by the Rolling Stones?"
RESPONSE:
  ai tool_call: transfer_to_invoice_info { }      // routes to the invoice sub-agent
```

### Call C — `invoice_agent`: decides to call the tool
```jsonc
REQUEST:
  tools: [ get_invoices_by_customer_sorted_by_date,        // params: {}  (customer_id injected)
           get_invoices_sorted_by_unit_price,
           get_employee_by_invoice_and_customer ]          // params: { invoice_id }
  messages:
    system: "You are the Invoice Information agent… answer ONLY the invoice part…
             if the request also asks about music, do NOT answer that part…"
    human:  "…How much was my most recent purchase? What albums by the Rolling Stones?"
RESPONSE:
  ai tool_call: get_invoices_by_customer_sorted_by_date { }   // empty args
```
→ runtime injects `customer_id="1"`, runs SQL, returns a `ToolMessage`:
`"Your invoices (most recent first):\n- Invoice #382: 2025-08-07 — total $8.91 …"`

### Call D — `invoice_agent`: turns the tool result into an answer
```jsonc
REQUEST:
  tools: [ …same invoice tools… ]
  messages:
    system: "…answer ONLY the invoice part…"
    human:  "…most recent purchase? …Rolling Stones?"
    ai:     (tool_call get_invoices_by_customer_sorted_by_date)
    tool:   "Your invoices (most recent first): - Invoice #382: 2025-08-07 — $8.91 …"
RESPONSE:
  ai content: "Your most recent purchase was Invoice #382 on August 7, 2025, for $8.91."
              // says NOTHING about music — lane discipline. Returns to supervisor.
```

### Call E — `supervisor`: sees music still unanswered → routes again
```jsonc
REQUEST:
  tools: [ transfer_to_music_catalog, transfer_to_invoice_info ]
  messages:
    system: "…check if any part is still unanswered and delegate again…"
    human:  "…most recent purchase? …Rolling Stones?"
    …       (invoice agent's $8.91 answer is now in history via full_history)
RESPONSE:
  ai tool_call: transfer_to_music_catalog { }
```

### Call F — `music_agent`: decides to call the catalog tool
The system prompt is built by the `dynamic_prompt` middleware, which injected
`loaded_memory` ("No saved preferences yet." on turn 1):
```jsonc
REQUEST:
  tools: [ get_albums_by_artist, get_tracks_by_artist,
           get_songs_by_genre, check_for_songs ]            // params: { artist } / { genre } / { song_title }
  messages:
    system: "You are the Music Catalog agent… The customer's known music
             preferences: No saved preferences yet. … answer ONLY music…"
    human:  "…What albums do you have by the Rolling Stones?"
RESPONSE:
  ai tool_call: get_albums_by_artist { "artist": "Rolling Stones" }
```
→ runtime runs `LIKE '%Rolling Stones%'`, returns `ToolMessage`:
`"Albums found:\n- Hot Rocks, 1964-1971 (Disc 1) (by The Rolling Stones)\n- No Security …"`

### Call G — `music_agent`: turns result into an answer
```jsonc
REQUEST:
  messages: …system… human… ai(tool_call)… tool("Albums found: …")…
RESPONSE:
  ai content: "We have the following albums by The Rolling Stones: Hot Rocks…,
               No Security, Voodoo Lounge."        // returns to supervisor
```

### Call H — `supervisor`: both parts done → combine & finish
```jsonc
REQUEST:
  tools: [ transfer_to_music_catalog, transfer_to_invoice_info ]
  messages: …both sub-answers now in history…
RESPONSE:
  ai content: "Your most recent purchase was Invoice #382 on August 7, 2025, for
               $8.91. Regarding the Rolling Stones, we have: Hot Rocks…, No
               Security, Voodoo Lounge."
  // NO tool_call → conditional edge ends the supervisor subgraph.
```

### Call I — `create_memory`: preference extraction (structured output)
Gate opened because `get_albums_by_artist` appears in the (full_history) messages.
```jsonc
REQUEST:
  tools: [ PreferenceProfile(favorite_artists: [str], favorite_genres: [str], notes: str) ]
  messages:
    system: "You maintain a customer's MUSIC preference profile… record ONLY musical
             taste. NEVER record purchase amounts, invoice details, dates, …"
    human:  "Existing profile: {favorite_artists: [], favorite_genres: [], notes: ''}
             Conversation: human: …Rolling Stones?  ai: We have the following albums…"
RESPONSE:
  ai tool_call: PreferenceProfile { "favorite_artists": ["The Rolling Stones"],
                                     "favorite_genres": [], "notes": "" }
```
→ `store.put(("memory_profile","1"), "user_memory", {...})`. The **$8.91 / Invoice
#382 are absent** — the PII-excluding prompt kept them out.

**Turn 1 total: ~9 LLM calls (A–I).**

## TURN 2 — "songs that match my preferences"

- **`verify_info`: 0 LLM calls** — `customer_id="1"` already in state → skipped.
- **`load_memory`: 0 LLM calls** — pure `store.get` → `loaded_memory="Favorite artists: The Rolling Stones"`.

### Call J — `supervisor`: route to music
```jsonc
REQUEST: tools:[transfer_*]  messages: system… human:"List some songs that match my preferences?"
RESPONSE: ai tool_call: transfer_to_music_catalog { }
```

### Call K — `music_agent`: now the dynamic prompt carries the saved taste
```jsonc
REQUEST:
  tools: [ get_albums_by_artist, get_tracks_by_artist, … ]
  messages:
    system: "…The customer's known music preferences: Favorite artists: The Rolling
             Stones. When the customer asks for 'songs that match my preferences',
             use these preferences to decide which artists/genres to look up."
    human:  "List some songs that match my preferences?"
RESPONSE:
  ai tool_call: get_tracks_by_artist { "artist": "The Rolling Stones" }
```
→ tool returns tracks → **Call L** (music agent final answer) → **Call M**
(supervisor finalize) → the list of Rolling Stones songs.

### Call N — `create_memory`: re-extract & merge
Idempotent — still `favorite_artists: ["The Rolling Stones"]`.

**Turn 2 total: ~5 LLM calls (J–N).**

## Takeaway

| What you see in the demo | What it is, technically |
|---|---|
| Supervisor "routes" to an agent | LLM returns `tool_call: transfer_to_<agent>` → runtime does a graph jump |
| Agent "uses" a tool | LLM returns `tool_call: <tool>{args}` → runtime runs the `@tool` function |
| Agent "answers" | LLM returns plain `content` (no tool_call) → conditional edge ends the loop |
| `customer_id` never appears in tool args | `InjectedState` hides it; the runtime fills it from verified state |
| Preferences influence turn 2 | `dynamic_prompt` injects `loaded_memory` into the music agent's system prompt |

Every decision is one request that returns `{name, args}`; every answer is one
request that returns `content`. That is the whole engine.
